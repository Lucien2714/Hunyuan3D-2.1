# 0001 多视图输入是一组不带方位的图片

## 背景

本项目要让 Hunyuan3D 2.1 接受同一物体的多张图片，生成几何和贴图，目的是让结果和每一张输入图都对得上，而不是只对得上其中一张、其余的面靠模型猜。

用户的要求是视角不固定：使用的人随手拍几张，不需要知道也不需要标注每张图是从哪个方向拍的。

有这些约束：

- 官方 2.1 只发布了单图的几何权重，没有多视图版本。
- 2.0 的官方多视图版本 Hunyuan3D-2mv 要求输入固定的正、左、后、右四个视图。上游代码里留下的 `DinoImageEncoderMV` 和 `MVImageProcessorV2` 就是按这个写的，每个视图编号对应一个固定方位。
- 上游发布的几何训练代码里，条件图是在球面上随机取视角、随机取视场角渲染的（`hy3dshape/tools/render/render.py` 的 `trellis_cond_camera_sequence()`），训练时从 24 张里随机取一张（`hy3dshape/hy3dshape/data/dit_asl.py` 的 `load_render()`），目标形状不随条件图的视角旋转。按这份代码训练出的模型，输出的朝向不取决于输入图的拍摄方向。官方权重实际是怎么训练的没有公开，这一点是从发布的训练代码推断的，没有在真实权重上验证过。
- 上游的贴图代码在结构上能接多张参考图，但只用了第一张，发布的训练代码每次也只用一张参考图。
- 开发机跑不了 2.1 的推理和训练，下面各方案的效果都没有在真实权重上比较过。

## 考虑过的方案

**方案一：固定四视图，照 2mv 的做法。** 输入是 `{视图名: 图片}`，每张图过 DINOv2 后加上按视图编号的位置编码，再拼接。

- 好处：2mv 证明了这个做法在 2.0 上可行；上游留有编码器和预处理的代码。
- 代价：使用的人要提供正、左、后、右的图并标对方位，随手拍的照片很难正好落在这四个方向上，不符合用户的要求。2.1 上仍然要训练才能用。

**方案二：一组不带方位的图片。** 输入是 1 到 N 张图片，没有视图名和方位编号，顺序不带含义。每张图各自预处理、各自过 DINOv2，模型自己从图片内容判断它们之间的关系。

- 好处：符合用户的要求。上游的训练数据格式本来就是每个物体若干张随机视角的图，不用改。不训练也有办法先做出基线：把各张图的预测平均，或者把各张图的 token 直接拼起来交给官方权重。
- 代价：模型拿不到方位信息，只能靠图片内容对应各张图。这个做法在 Hunyuan3D 上没有先例，2mv 只验证过固定视图。不训练的基线效果如何、训练后能好多少，都还不知道。

**方案三：带相机姿态的多视图。** 每张图带上相机参数，编码成姿态信息加到 token 上。

- 好处：模型能明确知道各张图之间的几何关系。
- 代价：使用的人不知道相机姿态，推理时要先用姿态估计模型算出来，这要引入新的预训练模型，估计错了会直接影响结果。模型输出的朝向是它自己定的，生成之前无法知道各张图的相机相对于输出坐标系在哪里，只能给出图与图之间的相对姿态。

**方案四：先把任意视角的图转成四个固定视图，再走方案一。** 用新视角合成模型把输入图转成正、左、后、右。

- 好处：后半段可以沿用 2mv 的做法。
- 代价：要引入一个生成模型。它生成的四个视图本身就可能互相不一致，也可能和原图不一致，这和本项目要解决的问题正好相反。2.1 上仍然要训练固定四视图的模型。

## 决定

采用方案二：多视图输入是同一物体的一组图片，1 到 N 张，不带视图名和方位编号，顺序不带含义。

理由：

- 只有方案二和方案四符合"视角不固定、不用标注"的要求。方案四多引入一个生成模型，而且会带来新的不一致。
- 上游训练代码的条件图本来就是随机视角，目标形状不随视角旋转，所以各张图只是同一个目标的多份证据，不需要告诉模型相机在哪。
- 方案二可以先做不训练的基线，在服务器上看到效果之后再决定要不要投入训练。其余方案都要先训练才有结果。

几何和贴图都在范围内：几何管线接受一组图片，贴图管线把同一组图片都作为参考图。

## 后果

- 上游 `MVImageProcessorV2` 的 `front=0, left=1, back=2, right=3` 不作为本项目的约定。模型里如果要区分图片，编号只表示"第几张"。
- cat3d 的调用方传一组图片，不传视图名。
- 先实现不训练的基线，在服务器上看效果，再决定是否微调。微调时用什么方式区分图片、训练哪些参数、数据怎么来，届时另写决策记录。
- 模型拿不到方位信息。如果基线和微调的效果都不够好，要回头考虑方案三，那时本记录要被新的记录取代。
- 贴图权重没有用多张参考图训练过。放开多参考图之后效果不好的话，要另外决定是否微调贴图模型。
- 输出朝向不取决于输入图的拍摄方向这一点是推断。如果在真实权重上发现不成立，方案二的前提就要重新评估。
